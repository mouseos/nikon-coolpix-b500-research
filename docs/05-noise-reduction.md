# ノイズリダクションを切る

## 結論

ノイズリダクション (NR) を切るメニューはない。
NR は画質 (IQ) データ側のパラメータで決まるソフトウェア処理であり、
撮影メニューの項目ではない。
切るには、IQ データの書き換えか、処理呼び出しの改変が必要になる。

## 根拠 1: NR は IQ パラメータの条件で呼ばれる

静止画処理 (PSOLID) の関数内 (0x803BC98C 付近) に、
IQ パラメータ構造体のバイト同士の比較条件が成立したときだけ
`"[PSOLID] sw reduceNoise"` を表示して NR 処理 (0x803E9F0C) を
呼び出す分岐がある (evidence/disasm-reduce-noise.txt、
参照元は evidence/xref-scan.txt)。

つまり、NR をかけるかどうかと、その強さは、コードの固定値ではなく
IQ パラメータ側の値で切り替わる設計である。
IQ データの実体は RO_RES/IQ/ の APPIQ.BIN (1,575,808 バイト) と
LENIQ.BIN (1,748,896 バイト) である。

## 根拠 2: もう 1 段のノイズ低減もある

撮影パイプラインには `post_denoise_yuvcb` という後段の
ノイズ低減コールバックも登録されている (登録箇所 0x806DA23C 付近、
evidence/xref-scan.txt)。静止画の絵作りには、少なくとも
reduceNoise と post_denoise の 2 段が関わる。

## 根拠 3: メニューに NR の項目がない

UI の文言テーブルに、静止画の NR を切り替える項目はない。
動画側の "Wind noise reduction" はマイク音声の風切り音低減であり、
画質の NR とは別物である。

## 見通し

「油絵のようになる」絵作りの主因の候補は、このソフトウェア NR の
段である。ただし、どの段がどの程度効いているかは、実写比較なしには
断定できない。
改変の筋は 2 つある。1 つは IQ データ (APPIQ.BIN / LENIQ.BIN) の
NR パラメータを弱めること。もう 1 つは reduceNoise の呼び出し条件を
コード側で無効化すること。どちらも、パラメータ構造の対応付けを
先に確定させる必要があり、その対応付けは未実施である。
