# 17 ファームウェアを壊した場合の復旧手段

## 結論

復旧の仕組みは、壊れた場所ごとに段階がある。本体ファームウェアが起動する範囲なら公式の更新で戻せる。本体が起動しなくても、ブート領域に独立した書き込みプログラム (Card ISP) が入っていて、SD カードから書き直せる設計になっている。ブート領域自体を壊した場合は、基板を開けてフラッシュへ直接書くしかない。

## 第1段階: 公式のカード更新

本体ファームウェアが起動する状態なら、公式アップデーターの firmware.bin を使って上書きできる。更新の検査はマジックの比較だけで署名検証がない (docs/02)。改造で壊しても、起動さえすれば正規のイメージで戻せる。

本体コードには、カードからフラッシュを更新する処理 (I43_UpgradeFlashFromCard) と、読みに行くパス `D:\firmware\firmware.bin` の文字列がある (ファイルオフセット 0x21A26D4)。

## 第2段階: ブート領域の Card ISP

ブート領域 (0x200〜0x93400) には、本体ファームウェアとは独立した「iCatch Card ISP」が丸ごと入っている。文字列から確認できた動作は次のとおり。

- SD カードをマウントし、ルートへ移動する。
- 更新前に、現在のファイルを SD の `D:\IBACKUP` へバックアップする (ファイル名は %04x.BIN 形式)。
- Boot 領域、FW0 領域、FW1 領域、DRAM パラメータ、リソースファイルを個別に書き換える。
- 書き込みごとに検証し、終わると自動で電源を切る。
- コンソールも持ち、`isp <ファイル>` でカード上の .BIN / .BRN から書き込み、`boot <ファイル>` でカード上のイメージから起動できる。

つまり、本体側が起動しない状態でも、ブート領域が生きていれば、カード経由で書き直す受け口が残る。

入り方は、ispBootMode という値で決まる (ispBootModeGet、ログ出力「ispBootMode:%d」)。通常の更新では、本体側の更新処理がこのモードを指定して再起動し、Card ISP が実際の書き込みを担うとみられる。本体が起動しない状態からでも入れる条件 (カード上のファイル検出やボタン操作) があるかは、コードの追跡がまだで未確認である。

同じ Card ISP 系の EKEN H9 では、更新ファイル (SPHOST.BRN) をカードに入れて電源を入れると自動で更新が始まる手順が公式に案内されていた。B500 のブートは別ビルド (docs/16) なので、同じ入り方が使えるとは断定できない。

## 第3段階: フラッシュへの直接書き込み

ブート領域まで壊した場合は、外部から書くしかない。ブート領域のコードには SPI フラッシュの扱い (Winbond のアドレスモード切替、SPI_RAW.BIN、spiUpdateDrampara) が含まれ、更新イメージ自体がフラッシュの生レイアウト (SUNP BURN FILE) である。基板上の SPI フラッシュにプログラマ (クリップと CH341A 等) でイメージをそのまま書けば、原理的には全領域を復旧できる。B500 基板のフラッシュの型番と実装形態は未確認である。

## 改造でブート領域は壊れるか

機能追加や自作ファームウェアの改造対象は、本体コードと FAT のリソース領域である。docs/03 から docs/15 で扱った改造 (RAW の開放、HDR の開放、ISO や動画の制限変更、UI の差し替え等) は全てこの範囲で収まり、ブート領域を書き換える必要はない。

ブート領域が壊れるのは、次の場合に限られる。

1. ブート領域自体を改造した場合。
2. 更新の書き込みが、ブート領域を書き換えている最中に中断した場合 (電源断ち等)。
3. 他機種の更新イメージを丸ごと書いた場合。ブート領域と DRAM パラメータが自機向けでなくなる。

安全線は、自作イメージでブート領域と末尾の DRAM パラメータ (DRAMPAR) を純正のまま残し、改造を本体コードとリソースだけに閉じることである。そうすれば、本体が起動しなくなっても Card ISP の受け口が残る。

なお、通常の公式更新がブート領域を毎回書き直すのか、差分があるときだけかは未確認である。毎回書き直す設計なら、残るリスクは書き込み中の電源断ちだけになる。

## 注意点

- Card ISP は Boot 領域自体も書き換え対象に含む。ブート領域に触る改造は、第2段階の受け口を失う危険と隣り合わせである。
- プラットフォームには PC から USB で書く工場用ツールの存在も確認している (EKEN H9 の配布物に USB_CAM.dll や SPC.BIN が同梱)。B500 がその経路に対応するかは未確認である。
