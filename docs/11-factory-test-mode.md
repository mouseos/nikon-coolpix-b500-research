# 工場・テストモード

## 結論

テストモード (校正モード) は実在する。電源投入時に自動で判定され、
次のどちらかで入る。

1. カメラ内部の校正データ (COLDDATA) のフラグが未完了の状態。
   工場出荷前の個体がこれに当たる。
2. 校正済みの個体では、SD カードのルートに `EnableTest.txt` という
   ファイルを置いて電源を入れる。

中身は、センサーとレンズの校正 5 項目、自動校正、各部の動作チェック、
校正データのバックアップと復元である。

## 入り方の根拠

電源投入時のモード決定処理 (0x805EBE30 付近) が、2 つの条件関数を
この順で呼ぶ (evidence/disasm-testmode-entry.txt)。

- 条件 A (関数 0x805C3BE4): 校正データ COLDDATA.BIN を読み、
  オフセット 0x1C のバイトを返す。
- 条件 B (関数 0x805C3BC0): `D:\EnableTest.txt` を開けるかどうかで、
  ファイルの存在を返す。中身は読まない。

分岐は次のとおりである。

- 条件 A が 0 なら、無条件でテストモードに入る。
- 条件 A が 0 でなければ、条件 B が真のときだけテストモードに入る。
  ファイルがなければ通常起動になる。

テストモードに入るときは、モード ID 0xF200000F と 0xF2000012 を
送信する。ディスパッチャ (0x805EC2D0) はモード ID の下位で
テーブル (0x80A8D170) を引き、ID 0xF2000012 の処理は
"START ENTER TEST Mode" と表示して校正モードの入口 (0x806EA9E0) へ
進む (evidence/disasm-mode-dispatch.txt)。

ファームウェア同梱の COLDDATA テンプレートでは、0x1C のバイトは
0 である (evidence/cold-bin-structure.txt)。
実機では個体ごとの校正データが内部の書き換え可能な領域にあり、
工場で校正を終えた個体はこのバイトが立つとみられる。
したがって、通常の個体で再現できる入り方は 2 の
`EnableTest.txt` を置く方法になる。ファイルは SD カードの
ルート (D:\) に置く。大きさや中身の指定はコードにない。

なお、校正モードの入口は、ハードウェアレジスタ 0xB000904C の
ビット 0 も読む。治具の接続検出とみられるが、入口の必須条件では
ない (読んだ結果で分岐するのは OIS 校正の追加処理だけである)。

## 中身

### 校正項目は 5 つ

校正モードの項目テーブル (0x80AB2FC4) に並ぶのは次の 5 項目で、
後ろに各項目の処理関数へのポインタ列が続く。

- OB (黒レベル)
- AGC (ゲイン)
- 50CM Focus (50 cm でのフォーカス)
- Light DPC (明所の欠陥画素)
- Dark DPC (暗所の欠陥画素)

項目は画面で選ぶ形式で、"CurCalibItemSelect" と選択番号を出す。
OIS (手ブレ補正) のゲイン校正も別にあり、"OIS Clbt Gain START"、
"Please Turn OIS machine" と表示して進める。

### 自動校正

"Start Custom Auto Calibration Mode" の表示があり、
校正項目を自動で流す入口 (Open Auto Clbt / Close Auto Clbt) がある。
ストロボ専用の入口 (EnterCalibrationMode_forStrobeTest) もある。

### 動作チェック

テストモード側には、各部の合否を表示するチェック画面がある。
表示項目は RTC、AGC、Iris、MSHUT (メカニカルシャッター)、ZOOM、
STROB (ストロボ)、SD、AUDIO、Video、Mem、Ver. である。
個別のテストとして、音のテスト (Sound Test)、LED テスト、
RTC テスト、カード書き込みテスト (`D:\CARD_WRT.TXT`)、
MTBF テストの表示も確認した。

### 校正データのバックアップと復元

BACKUP / RESTORE の処理があり、対象ファイルは BADPIX.BIN、
COLD.BIN、DEFTPXL0.BIN、DEFTPXL1.BIN、LSC.BIN、LDC.BIN、
BPVIDEO0〜4.BIN、VIDEOPIX0〜4.BIN である。
SD カード側の目印は `D:\CheckBP.txt` である。
HDR3 の保護一覧 (docs/01) と同じ顔ぶれで、校正データを
カードへ退避し、戻すための機能である。

### その他の切り替え

テストモード周辺には、撮影系の補正を個別に切る表示もある。
DBG on/off、LDC (レンズ歪み補正) on/off、CA (色収差補正) on/off、
DIST on/off、LSC (周辺光量補正) on/off である。
これらは校正時の確認用の切り替えとみられる。

## もう 1 つの隠しファイル

`D:\EnablePTPAP.txt` の存在を調べる関数 (0x805C3C24) もあり、
Wi-Fi 起動処理の中 (0x8069558C) で呼ばれて結果をフラグに保存する。
Wi-Fi 経由の PTP を有効化する、サービス用の入り口とみられる。
中身までは追っていない。

## テストモード側のファームウェア更新

テストモードのモジュールにも更新処理があり、こちらは
プロジェクト名と SECRET_PATTERN の一致を調べる表示がある。
通常の更新経路 (docs/02) の検査とは別物である。
パターンの実物は読み取っていない。
