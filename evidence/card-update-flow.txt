カード更新フローの関数マップ (本体イメージ、VA はベース 0x80000000)
2026-11-25、Ghidra 12.1.4 の解析と逆コンパイルで確認。

検査 (UI 側)
  0x806EF2E4  更新ファイル検査。D:\firmware\firmware.bin を開き、
              マジック "SUNP BURN FILE" (14バイト) を比較。
              ヘッダ [0x1C] のオフセットへ seek し 0x1EFF バイト読み、
              "VQSD_BRN:" 署名を走査して版数3値を大域変数へ格納。
              直後の7バイトが機種コード "KP35500" と一致すれば戻り値 2。
  0x806EF8A0  FW_FirmwareUpdate_Proccess。ISP 停止等の前処理の後、
              0x8088AB50 (パス, 完了コールバック 0x806EF750) を呼ぶ。
  0x806EF750  完了コールバック。D:\NTL\DATA.BIN の書き込み等の後処理と
              電源断 (0x806EF608) へ進む。

更新モジュール (Card ISP と共通、本体イメージ内)
  0x8088AB50  引数のパスとコールバックを受け、0x80895BF4 へ tail jump。
  0x80895BF4  モジュール入口。0x808958F8 を呼ぶ。
  0x808958F8  filePath を受け、ファイルをメモリへコピー (0x80894E48)、
              ヘッダ解析 (0x80895318)、更新本体 (0x80897EA0) を実行。
              ログ: "==copy file to memory==" "==parse file==" "==update=="
  0x80897EA0  更新本体。最大2回試行。
              - バックアップ対象ファイルの退避 (0x80897BE8)
              - "---format flash, updateMode:%d---"
                updateMode==0: 0x808968A8 (フォーマット)
                updateMode!=0: FW サイズ適合の確認のみ
              - "---res&fw update---" → 0x808977DC
              - "---recover backup files---" → バックアップ復元
              - 成功時 "===update success APwrOff:%d===" → 0x808979A4
                ("***** Card ISP complete! *****" と自動電源断)
  0x808968A8  フォーマット。サイズ適合を確認し、予約ドライブを
              フォーマットする (ログ "erase flash...,reserveDrvC:%d"、
              "fmt rsvA" "fmt rsvB" "fmt DrvC")。ブート領域は対象外。
  0x808977DC  リソースとファームウェアの更新。順に:
              1. リソースファイル更新 (0x808976D8)
              2. Firmware 更新: ctx+0x1C (ヘッダ [0x1C] のオフセット) が
                 非ゼロのとき 0x808970D4 (ファイルバッファ+オフセット,
                 サイズ取得 0x80896254, 検証フラグ)
              3. DRAM パラメータ更新: ctx+0x28 (ヘッダ [0x28]) が
                 非ゼロのとき 0x8089629C
              内容比較によるスキップは無い。
  0x808970D4  Firmware 書き込み。ストレージ種別で書き込み関数を切替
              (NAND 系 / 0x80157878 / SPI 系 0x8014D388)。
              書き込み後、検証フラグがあれば 0x80896EE8 で検証。
  0x80896EE8  Fw verify。書き込んだ領域を読み戻して元データと比較
              (docs/02 の「書き込み後 verify」と同一関数)。

予約領域の冗長レコード修復 (更新フローとは別)
  0x804DD17C  Boot / FW0 / FW1 のシステム情報レコード (3コピー) の
              チェックサムを検証し、不良コピーを正常コピーから書き直す。
              ログ "Update Boot Area %d" "Update FW0 Area %d"
              "Update FW1 Area %d" "Write System info %d" はこの処理。
              ブートイメージ本体 (0x200〜0x93400) の書き換えではない。
